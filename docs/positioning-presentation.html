02 · 정직한 진단

넷의 강점과 약점

Neo4j — 프로퍼티 그래프 DB

강 · 수십억 엣지 트래버설, 성숙한 Cypher, 운영도구, GDS 그래프 알고리즘

약 · OWL 추론 없음. is_a 전이추론·클래스 계층을 직접 짜야 함. 스키마가 느슨 — 온톨로지가 아니라 그냥 그래프

GraphDB / RDF — 트리플스토어

강 · 진짜 OWL 추론 — 전이폐포·클래스 포섭을 엔진이 공짜로. SPARQL, 표준 준수

약 · 무겁고 러닝커브 가파름. LLM 통합·의미검색 전무, 낡은 UX, 세팅 지옥

LangChain — 오케스트레이션

강 · LLM 생태계, 프로바이더 추상화, LLMGraphTransformer 추출

약 · 그래프는 얇은 래퍼. 영속성·TBox·추론 없음. "온톨로지"라 부르기 민망

LlamaIndex — PropertyGraphIndex

강 · LLM 그래프 추출 + RAG 결합. 우리 빌더와 가장 직접 경쟁

약 · 추출 품질 들쭉날쭉(환각), TBox 개념 약함, 위치·지도·학습데이터 export 없음

03 · 빈 자리

데이터 폴더 하나 던지면, 한 번에 —

넷 중 누구도 끝까지 하지 않는 다섯 가지.

01

LLM-native 구축

LLM이 TBox를 제안하고 인스턴스를 추출. 신뢰 데이터엔 환각 0 결정론 ingest 옵션

02

의미검색

별칭·정의까지 임베딩한 노드 벡터검색. 키워드 매칭이 아님

03

추론

TBox 클래스 계층, is_a 전이추론, 계층 롤업

04

위치성

위경도 + 카테고리 → 인터랙티브 지도, 그래프와 연동

05

학습데이터

triples / QA / surface-form JSONL — 모델 파인튜닝용 export

Neo4j는 1~5 전부 기본 미지원 · GraphDB는 추론(3)만, 1·2·4·5 없음 · LangChain/LlamaIndex는 1의 일부와 어쩌면 2, 3·4·5는 통합적으로 없음. 이 다섯의 통합이 곧 우리 제품이다.

빈 자리 = 우리 자리04
04 · 규율

우리가 의도적으로 하지 않는 것

✕ Neo4j의 저장엔진을 재발명하지 않는다

수십억 엣지 스토리지·클러스터링은 10년+ 걸린 물건. 이길 수 없고, 시도하면 초점을 잃는다.

✕ 완전 OWL DL reasoner를 재발명하지 않는다

GraphDB급 DL 추론은 별도 학문. 필요하면 넘긴다, 흉내내지 않는다.

✓ 우리는 저장하지 않고 지휘한다

상호운용(interop) — 백엔드 pluggable.
· 기본: 임베디드 경량 그래프(NetworkX + JSON) → 제로 세팅
· 대규모: Neo4j 어댑터
· 완전 추론 필요: RDF export → GraphDB로 위임

LLM-native 구축 계층을 소유한다 — 넷 다 미완인 바로 그 구간.

환각 0 원칙(aicoach 보험 온톨로지에서) — 결정론 record ingest + 검증 파이프라인. LlamaIndex가 흔들리는 곳에서 우리는 믿을 수 있다.

하지 않을 것을 정하는 게 전략05
