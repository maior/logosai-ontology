Logos · Ontology System Architecture

사실의 층 — 물으면, 검증 가능한 답을 출처와 함께

온톨로지의 단 하나의 일: 물으면 검증 가능한 사실을, 출처와 함께, 빠르고 결정적으로 돌려주는 것. 지식 표현·추론·grounded 검색·데이터셋 추출이 전부 이 하나를 위해 존재한다. 이 문서는 그 시스템을 층·저장·검색·경계로 나눠 그린다.

1 한 장의 그림

두 개의 반쪽이 한 디렉터리에 산다 — 커널(사실의 층)과 에이전트 스택(라우팅). 경계는 위치가 아니라 의존 방향으로 정의된다. 커널은 에이전트 스택을 모듈 레벨로 import 하지 않는다.

그림 1 — 소비자는 REST 만 호출한다. 커널→server→frontend 방향 의존은 0. 에이전트 스택은 지연 로딩으로 격리돼 커널을 오염시키지 않는다.
왜 이 경계인가 (실측 진단)

온톨로지 프로젝트가 3개인데 Logos/ontology 채택은 0이었다. 기능이 아니라 import 비용 때문이다 — aicoach 는 KG 엔진 API 를 그대로 베끼면서도 import 하지 않고 재구현했고, 코드에 이유를 남겼다: "without pulling its heavy transitive deps." 축 1(커밋 69779fa)에서 KG import 시 딸려오던 logosai 31개 모듈을 0으로 만들었다.

2 저장 스택 — PG=진실, ES=투영

진실은 PostgreSQL 한 곳에 산다. Elasticsearch·벡터 캐시는 그 진실의 투영이다 — 언제든 재생성 가능하고, 죽어도 온톨로지가 같이 죽지 않는다.

그림 2 — 쓰기는 진실(PG)에 먼저, 그다음 투영(ES/벡터)으로 미러. 읽기 경로도 PG 하이드레이트. ES tier 는 노드 수가 아니라 "하이브리드가 필요한가"로 고르는 명시 선택.
계층역할특성
PG진실의 단일 출처 — 그래프·원문 청크소유 NS 는 ontology 스키마, 외부는 원천 스키마(aicoach) 직접 하이드레이트
VEC의미 검색 벡터 — 노드·청크memory→npy→ES 3-tier · npy 는 build-once 디스크 캐시 (콜드스타트 8.5s→0s 실측)
ES하이브리드(BM25+dense) 검색조문번호·고유명사처럼 문자 그대로 맞아야 하는 질의 담당 · 명시 선택 전용
NX인메모리 networkx 그래프PG 에서 1회 하이드레이트 후 상주 — 뷰·통계·확장의 즉답 층

3 검색 스택 — 그래프-조건부 하이브리드

이 시스템의 차별점: 온톨로지·벡터·키워드 세 신호의 결합. 질의를 그래프로 확장한 뒤(별칭·is_a 폐포), 청크 채널과 그래프 채널을 RRF로 융합한다. 하드코딩 어휘 없이, 확장어는 전부 그래프에서 읽는다.

그림 3 — 두 채널 점수는 의미가 달라(청크 코사인 vs 노드 코사인) 선형 가중합이 성립하지 않는다. 그래서 RRF(순위 융합). 모든 히트는 matched_via/channels를 달고 나온다.

4 인제스트 파이프라인 & 출처 사슬

인제스트

chunk_id는 내용 해시(sha1)라 재빌드해도 중복이 안 쌓인다. JSONL 은 한 줄이 깨져도 나머지가 산다.

출처 사슬 (provenance)

노드 → 청크 → 원문 char 오프셋

불변식: original[char_start:char_end] == chunk.text. 깨지면 인용이 엉뚱한 곳을 가리켜 무의미해진다.

데이터셋 evidence = 원문→개체 추출 지도학습쌍. 양쪽 다 실제 데이터 → 환각 0.

6 온톨로지 ↔ 에이전트 — 계산기와 사람

"온톨로지가 검색한다"는 결정론 계산기가 돈다는 뜻이다 — numpy 코사인·networkx 순회·RRF 산수, LLM·추론 루프·자율 판단 0. PostgreSQL 이 SELECT 를 "실행"하지만 에이전트가 아닌 것과 같다. agentic AI(logosai)는 그 계산기를 언제·어떤 질의로 쓸지 판단하고 결과를 답으로 조립하는 층이며, 계산기 계산 자체를 대신하지 않는다. 둘은 경쟁이 아니라 계산기와 사람처럼 상보적이다.

사람 = 에이전트 (판단)

agentic AI · logosai

  • 무엇을·어디(namespace)서 물을지 결정
  • 질의 재작성 · 재검색(multi-hop) 판단
  • 근거 발췌 → 답 조립 + 번호 인용
  • 환각 통제 · graceful degrade · 오케스트레이션

grounded_qa_agent.py · SimpleAgent

계산기 = 온톨로지 (도구)

결정론 검색 · 9274

  • 진입: 임베딩 코사인 semantic_search
  • 확장: is_a 폐포 + 인접 (networkx)

graph_retrieval.py · 순수 함수

계산기를 에이전트에 "담기" — 참조로, 복사로 아님

계산기는 에이전트라는 기능 단위로 포장돼 에이전트 메시에 들어간다(grounded_qa_agent 가 능력을 광고하고 협업). 단 "담는" 방식이 성패를 가른다 — 코드를 복사하면 안 되고, 클라이언트로 참조해야 한다.

프린터 하나(온톨로지)를 여러 드라이버(어댑터 에이전트)가 참조로 꽂아 쓴다. 계산기가 각 에이전트에 복사되지 않는다.
담는 방식무엇을 넣나결과
✅ 참조계산기의 HTTP 클라이언트만 (call_tool_http("/retrieve"))계산기 한 곳, 모든 에이전트 공유. 고치면 전원 수혜. 같은 출처·같은 결정론
❌ 복사검색 코드 자체를 에이전트 안에 재구현에이전트마다 계산기 중복 · N배 유지·N배 버그 · 출처 제각각
복사로 담았다가 실패한 실증 — aicoach

aicoach 는 검색 계산기를 자기 코드에 복사했다: "Mirrors the Logos SimpleKnowledgeGraphEngine API (…) without pulling its heavy transitive deps" (backend/app/kg/graph.py:1-10). 결과 — 온톨로지 프로젝트 3개, Logos/ontology 채택 0. 각자 계산기를 내장하니 공유가 안 됐다. 최근 작업(aicoach 라이브 직접 사용, 복사본 삭제)이 바로 이 복사 → 참조 전환이다.

환각이 0인 이유 — 검색을 결정론 도구로 떼어놓았기 때문

에이전트가 검색까지 LLM 으로 "직접" 하면 출처를 지어낸다. 검색을 결정론 계산기로 떼어놓으니 → 같은 질의에 같은 근거 + 출처(청크·조항). 에이전트는 그 발췌 안에서만 답을 조립하고 문장마다 [N] 인용하므로 환각이 0 이다. 계산기를 도구로 만든 것이 agentic AI 를 신뢰 가능하게 만든다 — 에이전트가 계산기를 품되, 계산기가 되지는 않는다.

7 캐시 계층 제안 · 미구현

현재 /retrieve(ES 하이브리드 + 그래프 확장 + RRF)와 쿼리 임베딩은 매 요청 전액 재계산한다. CacheManager 인터페이스는 있으나 서빙 경로에서 인스턴스화·사용되지 않는다(구현≠사용). 여기에 두 층의 캐시를 붙이면 반복·유사 질의의 지연을 크게 줄인다.

그림 4 — 제안 캐시 2층. HIT 이면 임베딩·ES·그래프·RRF 를 통째로 건너뛴다.

설계 원칙 (이 프로젝트의 기존 규율과 정합)

  • 무효화가 핵심. 소유 NS 는 네임스페이스별 generation 카운터를 쓰기(인제스트·재색인·PATCH·삭제)마다 증가시키고, 캐시 키에 포함 → stale 이 절대 서빙되지 않는다(명시적 purge 불필요). 기존 content_hash/mtime 접근과 같은 결.
  • aicoach 원천은 TTL. 쓰기가 aicoach 쪽에서 일어나 온톨로지가 관측하지 못한다 → generation 훅이 안 뜬다. 짧은 TTL(예 60–300s)로 신선도를 담보. (커널/원천 경계의 정직한 한계)
  • 결정적 층은 무효화 불요. 쿼리 임베딩은 같은 (model, text)면 항상 같다 → LRU 만으로 안전.
  • degrade-safe. 캐시 미스·백엔드 다운 → 그냥 계산. 캐시는 절대 하드 의존이 아니다(ES degrade 철학과 동일).
  • 있는 걸 쓴다. 새 추상 대신 이미 스캐폴딩된 CacheManager 인터페이스를 배선 — "구현≠사용"을 반복하지 않는다.
  • 먼저 측정. TTL·LRU 크기·RRF_K처럼 상수는 골든셋으로 측정해 정한다(지어낸 상수 금지). 우선 인프로세스 LRU, 다중 인스턴스가 되면 그때 Redis.
권장 순서

① L1 임베딩 LRU (가장 싸고 안전, 즉시 이득) → ② NS generation 카운터 도입(쓰기 지점에 훅) → ③ L2 결과 캐시(소유 NS = gen 키, aicoach = TTL) → ④ /admin/system에 hit-rate 노출로 효과 측정. 전부 additive · degrade-safe.
