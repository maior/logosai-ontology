Ontology Storage Engine · 축 5

사실의 층을 다시 짓다 — PostgreSQL = 진실, Elasticsearch = 투영

인메모리 그래프의 한계를 넘어, 수천만 객체를 인덱스로 서빙하는 저장 엔진. 팔란티어 파운드리의 원리를 우리 규모로 이식하되, 신뢰 등급·근거 추적·커널 경계라는 우리만의 축으로 차별화한다.

한 문장 요약
온톨로지의 단 하나의 일은 “물으면 검증 가능한 사실을, 출처와 함께, 빠르고 결정적으로 돌려주는 것”이다. 이 엔진은 그 답을 스캔이 아니라 인덱스로, 휘발이 아니라 트랜잭션으로 만든다.

1 왜 다시 지었나

기존 온톨로지는 네임스페이스마다 인메모리 NetworkX 그래프 + 통짜 JSON 체크포인트였다. 기능이 아니라 구조가 한계였다.

기존 (Before)

저장프로세스 RAM 안 그래프 전체
카운트·필터O(N) 파이썬 스캔 → COUNT_CAP 근사 밴드에이드
영속JSON 통째 재기록 (트랜잭션·무결성 없음)
검색부분일치 문자열 스캔
상한수십만 ~ 백만

재설계 (After)

저장PostgreSQL 인덱스 테이블 (진실)
카운트·필터인덱스 GROUP BY → 진짜 카운트
영속ACID 트랜잭션 · 행 단위
검색Elasticsearch BM25 + 파셋 aggregation
상한인덱스로 수천만 확장

2 아키텍처 — 세 개의 층

소비자(관리 콘솔·브리지 에이전트)는 GraphStore seam이라는 단일 인터페이스만 본다. 그 뒤에서 백엔드가 바뀌어도 반환 payload 는 동일하다 — 소비자는 저장소를 모른다.

그림 1 — 소비자는 seam 만 본다. 백엔드(PG·ES·NX)는 교체·degrade 되어도 계약이 같다.

3 데이터 흐름 — 쓰기와 읽기

그림 2 — 빌더는 NetworkX 에 병합하고, 그 결과를 PG(진실)+ES(투영)로 멱등 미러한다. 읽기는 브라우즈=PG 인덱스, 검색=ES BM25 로 갈라진다.

4 핵심 설계 결정

결정선택왜
진실 원본PostgreSQL ACID·무결성·트랜잭션. 검수/묘비/감사가 자연스럽다. ES 는 재색인으로 언제든 복구되는 투영이라 진실이 될 수 없다.
노드 검색ES BM25 고유명사·조문번호는 문자 그대로 맞아야 한다 — 임베딩만으로는 놓친다. 청크 벡터 검색은 별도 인덱스가 담당.
이전 단위네임스페이스 ONTOLOGY_PG_NAMESPACES 로 하나씩 전환. 전역 플래그를 안 건드리고 무중단 점진 이전.
실패 모드degrade PG/ES 불가 시 NetworkX 로 자동 강등 — 온톨로지가 인프라 때문에 같이 죽지 않는다.
스키마 배치기존 DB 안 ontology 스키마 least-invasive. namespace 컬럼으로 다중화(DB/스키마-per-namespace 아님).

5 차별점 — “우리만의” 사실의 층

단순히 팔란티어를 베낀 게 아니다. 같은 뼈대 위에 온톨로지만의 축을 세웠다.

1. 신뢰 등급을 1급 시민으로
모든 노드가 trust(authoritative·unknown·summary·unset)를 갖고, 수집 시점에 지정된다. ES 파셋이 신뢰 분포를 즉시 보여준다 — “이 답이 얼마나 믿을 만한가”가 검색 결과에 딸려 온다.
2. 근거(provenance) 사슬
노드 → 청크 → 원문 문자 오프셋까지 이어진다. “어디서 알았나”에 출처로 답한다. 순수 벡터 RAG 가 “그럴듯한 답”을 줄 때, 이 엔진은 인용 가능한 답을 준다.
3. 온톨로지·벡터·키워드 세 신호의 결합
BM25(문자 그대로) + dense_vector(의미) + 그래프 확장(별칭·is_a 폐포)을 RRF 로 융합한다. 세 신호 중 하나만 쓰는 시스템이 놓치는 질의를 잡는다.
4. 커널 경계 — 무겁지 않게 채택 가능
psycopg·elasticsearch·torch 는 전부 선택적 extras + lazy import. 커널을 import 해도 이들이 없어야 죽지 않고, 없으면 품질만 내려간다(degrade). 온톨로지 채택을 막던 “heavy transitive deps” 문제를 구조로 제거.
5. 브라우즈 ≠ 검색
정확 필터+페이지네이션(결정적, PG 인덱스)과 관련도 랭킹(ES BM25)을 분리했다. 팔란티어 Object Explorer 의 좌측 파셋·중앙 목록·랭킹 검색을 우리 데이터 모델로 재현.
