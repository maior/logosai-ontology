벡터의 일생04
04 · 왜 이렇게 했나

벡터를 진실의 원천으로 취급하지 않는다

① 재생성 가능한 파생물

벡터는 그래프에서 언제든 다시 만들 수 있다. 원본이 아니라 캐시. 원본(그래프)만 저장하면 충분하다.

② 모델이 바뀔 수 있다

임베딩 모델을 교체하면 예전 벡터는 무의미. 저장해두면 마이그레이션 부담만 늘어난다.

③ 규모에 맞는 단순함

~1,000 노드에서 numpy 행렬곱은 밀리초. 벡터 DB 의존성을 추가할 이유가 없다. (semantic_index.py 설계 주석)

④ 관심사 분리

그래프 = 지식(영속). 인덱스 = 검색 가속(휘발). 둘을 섞지 않으니 각각 독립적으로 교체·확장 가능.

설계 근거05
